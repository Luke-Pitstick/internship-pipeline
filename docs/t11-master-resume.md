# T11 — Master résumé from confirmed saved facts

Implemented October 6, 2026. Settings → Resume Generation now generates, previews and downloads a master PDF from the saved structured profile without uploaded LaTeX, model credentials or notifications.

## Delivered acceptance evidence

- `resumes/master_template.py` owns one two-page, letter-sized template. It renders the saved name/email, every confirmed fact, separately identified education entries and skills supported by those facts. Unknown claims/education and preferred skills are excluded. Its manifest preserves the exact profile revision/saved timestamp, template revision/content digest, stable fact/education IDs and their original structured values, skill provenance and omitted unknown IDs. Each factual string must survive readable PDF extraction, including numbers, dates, contact text and punctuation.
- `resumes/master.py` uses the existing SQLite `tasks` queue with the `master_resume` kind and existing lease heartbeat. POST queues work immediately; the supervised `master-resumes` CLI role compiles independently of model readiness or collectors. It reuses `LatexCompiler` with a maximum 60-second deadline, no shell escape, restrictive file access, process-group timeout termination and overflow-log checks. Existing PDF validation enforces readable content, page count, contacts and page bounds; the master validator additionally checks every required factual string.
- Character-by-character escaping ensures candidate text cannot introduce TeX commands, file reads or process execution. The template supports Latin letters and common punctuation; unsupported characters produce an explicit instruction to revise the saved field. Real compilation tests render literal `\input{/etc/passwd}` and `\write18{...}` text as ordinary résumé content. No uploaded source is passed to the compiler.
- The `master_resumes` SQLite record and unique task key retain exact immutable revision provenance. Concurrent requests share one task; unchanged successful output is reused. Missing/corrupt/symlink output is rejected and can be regenerated deliberately. Losing the worker lease prevents publishing its artifact. A profile save immediately suppresses old results from the latest endpoint and UI; historical private artifacts retain their original revision rather than being relabeled.
- PDF files use private directories (0700), files (0600), fixed generated filenames, bounded reads, no-follow descriptor opens and stored SHA-256 verification. The owner-only same-origin router provides GET/POST `/api/master-resume` and GET `/api/master-resume/{key}/pdf`; POST uses the existing CSRF/origin/session boundary. The PDF route uses inline/attachment disposition, no-store and SAMEORIGIN for authenticated embedded viewing. Responses do not expose server filenames or private manifests.
- The component uses the saved revision, disables generation while the draft/import is dirty, polls queued work, shows actionable compile/overflow/storage/profile errors and offers preview/download. Revision changes discard stale browser results. The existing job-specific generation implementation remains intact; T12 explicitly owns its replacement and policy integration.
