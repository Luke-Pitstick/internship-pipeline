## Flow and durable state

The existing owner claim/sign-in boundary leads an empty installation to `/setup/`. The sequence is models, profile/résumé review, job filters, saved search, optional integrations, final configuration preview and first results. `onboarding_state` in the existing jobs SQLite database stores the current step, reviewed steps, model deferral, separate email/Sheets choices, first-run identity and explicit completion. Closing the browser or restarting the application preserves progress. Existing observed jobs remain accessible while the navigation offers Continue setup; incomplete setup does not make a stored workspace unavailable.

`SettingsWorkspace.svelte` is the shared implementation of both the separate Settings page and the guided steps. It reuses the existing model, reviewed résumé import, profile, filter, source, SMTP and Sheets components and their APIs. There is no second owner account, profile, credential store, connection probe or queue. A profile with explicitly reviewed unknown fields can be saved and used for collection. The owner can defer models, which leaves fit/evaluation or tailored generation pending; résumé import continues to extract locally without inference.

Email and Sheets independently accept Connect or Skip, covering all four combinations. Connect requires current verified readiness, while Skip removes that setup prerequisite and leaves a failed service visibly failed. Skipping an already enabled integration does not silently disable its saved configuration; the preview shows the chosen setup path and actual saved enablement separately. Incomplete means missing/unverified settings. Failed means an application-owned recorded model probe, SMTP operation or Sheets operation failed. Sheets access-test results now persist only revision and a sanitized success/failed/invalid status in the integration's own `sheets_tests` table; a failed access probe revokes tested readiness, and a new configuration revision does not inherit the old failure. Invalid/missing fields remain incomplete and require correction.

The setup explanations distinguish hard eligibility constraints and confirmed authorization/availability/education, soft preferences and rubric fit, and fact-grounded draft generation. Fit measures rubric alignment, not interview probability. Full source inventory is stored independently of model review budgets. Initial backlog review remains explicit. Automatic generation is off by default, and the final preview shows its actual current rules and enablement. Discovery, assessment, drafts, delivered alerts, owner-reviewed spreadsheet changes and Applied remain separate; finishing setup never submits or marks an application.

## Preview and correction contract

GET `/api/onboarding` reads authoritative current profile, model, search, generation, email and Sheets state. The final preview includes profile and connection revisions, confirmed-fact count, hard/soft preferences, selected models/readiness, active/paused searches and schedules, model-work limits, generation rules and integration choices/enablement. It contains no model key, SMTP password, service-account material or private path. It is owner authenticated and uses the existing no-store response boundary.

POST `/checkpoint` persists review choices, and POST `/visit` saves the current step. POST `/start` requires the displayed preview fingerprint and selected active search. The existing shared SQLite writer transaction rejects configuration changes since that preview and atomically admits the existing search-run/queue work plus its durable onboarding run identity. Replaying a start while viewing that run cannot create a second run. Owners deliberately return to the preview to correct/retry a failed or empty search. POST `/finish` requires a collected observed job and records completion; zero-result searches stay inspectable and offer correction/rerun. The same owner, session, CSRF and origin protection applies to every mutation.

Correction links open `/settings/?setup=1#<category>` in Profile, Job Filters, AI Models, Sources, Resume Generation or Notifications & Integrations. Settings includes a return link to the saved setup step. Saved-source correction exposed and fixed an existing reactive-proxy clone error: editing now clones a Svelte snapshot, so changing a failed source actually loads and updates its current saved revision. Mobile navigation wraps the added Continue setup action rather than overflowing.
