# T07 — one company board, browser Run, durable collection and Jev review

October 6, 2026. **Implementation complete; fresh-container/live-browser Milestone A acceptance remains blocked/unverified.** Owners can save one public Greenhouse company board under Settings → Sources, run it there or from Jobs, and inspect persisted progress/results without notification or spreadsheet configuration. Automatic résumé generation remains off. The browser integration was exercised through real authenticated API requests, SQLite, collection work and the production Jev request/validation path with explicitly synthetic ATS data and mocked HTTP model responses. This is not a live model-quality or fresh-container acceptance claim.

## Criterion evidence

| T07 criterion | Delivered behavior and verification |
| --- | --- |
| One supported source and manual Run | `search_runs.py` validates a company name and Greenhouse token; it constructs an HTTPS URL on the fixed supported host, rejects URLs/path/query injection, and persists optimistic source revisions. Authenticated GET/POST `/api/search-settings`, POST `/api/search-runs`, GET `/api/search-runs/current` are mounted. `SourceSettings.svelte` implements Save/Discard and disables Run for an unsaved source. The real browser/API test saves and reloads the board, runs it twice, and checks mobile layout. |
| Store/evaluate without delivery | `search-runs` worker consumes existing shared `Queue` tasks with kind `collection_run`; ingestion commits jobs regardless of model/profile readiness. T06's independent matcher consumes its existing tasks and reconciles open backlog jobs. Browser and Python tests verify authoritative assessments with zero artifacts/deliveries. CLI collector reads its profile snapshot directly, without constructing inference/generation clients. Worker startup and `serve` no longer require a destination except for the delivery role. |
| Durable status/counts/errors/results | Run metadata, frozen source configuration, fetched response checkpoint and run/job membership persist in SQLite. Source errors, incomplete inventories and worker-exhaustion errors are visible. Counts read current persisted assessments and separate evaluated, pending, review, recommended, rejected, evaluation-error and inactive jobs. No GET invokes inference. Browser test observes 2 collected/2 evaluated, reloads persisted state, and observes a synthetic source failure with needs-attention state. T06's model rejection gate stays closed; model violations remain review results. |
| Identity/backlog/timestamps/incomplete safeguards | Existing ATS normalization and `Store.ingest` retain identity/content dedup, original first observation, source timestamp kind, first-snapshot backlog labels, and two-complete-inventory closure rules. Dedicated tests cover repeated runs, backlog versus newly observed jobs, source/first-observed separation, and repeated incomplete failures leaving absent jobs open. Browser targets are excluded from periodic legacy collection until explicit T08 scheduling exists. |
| Safe restart and generation off | Shared Queue leases own the work. Source configuration is frozen at Run time. A fetched response survives interruption and is replayed without another public request. The narrow optional `Store.ingest` checkpoint commits run membership/counts and task completion in the same transaction as inventory reconciliation. Tests deliberately fail after the checkpoint and verify full rollback, restart without refetch, and missing-job counters incrementing once; active lease and concurrent Run tests prevent duplicate work. No automatic résumé task is enqueued. |

`search_runs` stores progress/result metadata rather than introducing another task queue. Existing `tasks` remain the sole work ownership/retry authority. Collected runs can finish source work while Jev remains pending; closing the browser does not affect either worker. A later Run can proceed independently of slow or misconfigured matching, and profile/model revisions continue to invalidate results through T06.

Tested Save, Run, persisted evaluated counts after reload, repeated Run, source failure, 390px viewport with no horizontal overflow. `web/test-results/t07-search-mobile.png` is ignored and was visually inspected.
- Svelte check: **0 errors, 0 warnings**; static production build passed. Ruff passes owned modules/tests; mypy passes search_runs/storage/collection. Broader shared-code checks are owned by the parent as T09/T12 changes integrate.

No public posting payload was committed or sent to a model, and no actual profile, token, notification or application was consumed.
