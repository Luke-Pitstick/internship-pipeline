# Original LaTeX resume generation contract

The current generator edits the candidate's original `.tex` and compiles that same template. It never reconstructs the document from a PDF, generates a replacement template, calls Resume Matcher improvement/import APIs or falls back to the previous Swiss renderer. Existing stored PDFs remain readable as legacy previews; `ResumeArtifact.engine` defaults to `legacy-resume-matcher` for old records and is `original-latex` for new artifacts.

## Source and deployment requirements

Set `CandidateProfile.master_resume_path` to the original UTF-8 `.tex` file, at most 512 KiB. A missing source or `.pdf` fails closed with an actionable source-required error before Codex runs or a legacy checkpoint is consulted. Removed configuration keys fail ordinary schema validation. The original source has now been supplied and locally verified without edits. Deployment must complete its model/config and real compiled-draft acceptance checks before unpausing generation.

The verified candidate source uses the Jake Gutierrez template with 16 existing `\resumeItem{...}` bullets. Known nested `\textbf`, `\textit`, `\emph` and `\underline` formatting and escaped punctuation are retained. Comments are immutable, multiline bullets are supported and unknown nested macros such as `\href` are excluded from editing. An unfamiliar template with no permitted bullet spans fails closed; extend the explicit source policy after inspecting the actual template instead of regenerating its layout. Headers, earned job titles, employers, dates, section order, expertise lists, preamble, fonts, margins and all text outside permitted bullet edits stay byte for byte unchanged. This initial policy does not add headline or expertise sections; a separately existing headline can be considered only after the original source establishes a safe content slot.

The worker needs Codex CLI 0.153.0, Node 22, a writable persistent `CODEX_HOME` with a saved ChatGPT subscription login, and `pdflatex`. `Settings.resume_model` defaults to `gpt-5.6-sol`; configuration can set `resume_model` or environment `RESUME_MODEL`. `Settings.resume_reasoning_effort` supports `low` and `high`, defaults to `low`, and is part of generator identity and generation keys. The service always passes this explicit model to Codex; unavailable models fail rather than silently switching. Debian deployment can start with `texlive-latex-extra` and `texlive-fonts-recommended`; add packages/fonts only when the original source requires them. `texlive-fonts-extra` has not been established as necessary. The original must compile as a standalone source using installed TeX packages. Private included source/assets are not automatically copied or uploaded; missing assets/packages produce an actionable compile failure. No Resume Matcher credentials or renderer service is required for new generation.

## Codex and editing policy

The saved subscription is used through documented [noninteractive Codex execution](https://learn.chatgpt.com/docs/non-interactive-mode) and structured output. The adapter removes `OPENAI_API_KEY`, forces `forced_login_method="chatgpt"`, passes the configured resume model explicitly, ignores user config/rules, uses an ephemeral read-only session and disables tools, web search, apps/plugins/hooks, computer use and delegation. Source/job text is untrusted data on stdin. Output is capped at 512 KiB. Deadline expiration kills and reaps the subprocess group; private temporary files are removed. Synthetic subscription probes rejected gpt-6-luna and gpt-6.1-sol as unsupported. The user then approved gpt-5.6-sol with low reasoning, and a synthetic invocation using the exact restricted adapter flags succeeded. No silent model or billing fallback is used. No authentication files are read or copied by the adapter.

The edit-plan schema contains up to 40 replacements and up to 20 ranked verbatim job-description phrases, with supporting fact IDs and explanations. List order is importance rank; unsupported keyword phrases can have no supporting IDs and cannot authorize resume claims. A replacement must match one unique substring of an allowed bullet, have supported nonempty fact IDs, preserve exact character count and sentence punctuation count, preserve every LaTeX command/brace/special symbol/newline/tab at its original position, preserve protected factual text/months, and preserve the exact original numerical claims. New substantive vocabulary must occur in that edit's old text or cited factual records/skills; a small explicit set of ordinary connective/action words is allowed. Unknown skills/qualifications/numbers and overlapping edits fail before compilation. These gates prevent provable additions but do not prove that a supported rewrite preserves meaning; every output needs factual review.

Instructions about executive experience, deals or qualifications in reference examples are not candidate facts. Job requirements cannot establish candidate skills. Earned experience titles and unsupported degree/eligibility claims cannot be rewritten from the target job. The source policy changes existing permitted prose only; it never adds sections, bullets, sentences, metrics or expertise lists. Equal character counts cannot guarantee identical line wrapping because glyph widths differ, so visual review remains necessary.

## Compilation, checks and provenance

`ResumeService(settings).generate(job, match, profile, checkpoint=None)` compiles the untouched original as a baseline, then compiles the exact source with verified text replacements. The compiler runs two `pdflatex` passes with `-no-shell-escape -interaction=nonstopmode -halt-on-error -file-line-error`, restrictive TeX input/output settings and the remaining generation deadline. It uses a private temporary directory and suppresses source-bearing compiler logs from operational errors. Missing compiler/packages/assets, failed compilation, missing/excessive PDF output and TeX-reported overfull boxes fail closed.

PDF checks require readable unencrypted pages, the configured page limit, the same page count as the original baseline, candidate name/email/protected values and all retained/edited bullet content. LaTeX syntax outside permitted replacements is preserved by applying source offsets, not by comparing a regenerated template. The pipeline preserves the source file bytes and does not replace its date punctuation to suit another renderer. PDF-only comparison accounts for TeX apostrophe/dash typography and spacing omitted at known formatting-command boundaries; it still checks every letter, metric and ordinary word boundary. This avoids treating bold glyph-run extraction artifacts as missing source facts. All artifacts carry semantic-review and line-wrapping-review warnings. A compiled, extractable PDF does not establish pixel-identical formatting or absence of every possible clipping problem; final visual acceptance uses the candidate's original template after source provisioning.

The generation key includes engine/source-policy revisions, exact original source SHA-256, profile revision, job ID/description, role family, selected fact IDs, generator model/schema/prompt identity and compiler identity. Private fsynced atomic checkpoints cache the verified edit plan; a failed/restarted compilation reuses that plan rather than repeating Codex inference. Nonblocking process locks serialize the same generation and baseline. No remote creation requests or ambiguous job uploads exist in the new generation path.

Each artifact directory contains `resume.tex`, `resume.pdf`, `changes.json` (ranked keywords, exact replacements, reasons, fact IDs and source hash) and `manifest.json`. Manifests verify source/PDF/report hashes and record `status=review_needed`, source-policy engine and the serialized artifact. Missing/corrupt artifacts or reports are rebuilt from the cached verified plan without another model call. LaTeX and legacy engines have different keys, so a saved Swiss PDF cannot satisfy a new original-source request. Existing legacy records default to the legacy engine and remain retrievable through ordinary artifact storage; no renderer HTTP client remains. Persist any required old PDFs locally before suspending the old renderer; new generation has no dependency on it. Obsolete `resume_matcher_url` and `master_resume_id` settings are removed.
