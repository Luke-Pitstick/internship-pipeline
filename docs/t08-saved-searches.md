# T08 — Saved searches, schedules and persisted run admission

October 6, 2026. Implementation and synthetic integrated acceptance pass. The single Greenhouse setting is replaced by multiple independently versioned saved searches. Greenhouse, Lever and Ashby accept company names/board tokens; JobSpy exposes term, location, country, supported sites, window age and result count. No second queue or collector runtime is introduced.

Owners can run, pause/resume or remove a saved search, cancel remaining model admission, and inspect bounded run history. Immutable run snapshots survive edits to saved settings. Daily HH:MM schedules use validated IANA zones, skip nonexistent DST times, run repeated times once, persist next run and admit one collection at a time per search. Scheduler execution lives in the existing independent search-runs worker, so browser closure does not stop collection. Polling reloads persisted history on initial load, visibility and reconnect.

Run-level jobs/calls/token ceilings are configurable independently of T06 global retry caps. Atomic run_reservations record admission before assessment or tailored-generation HTTP I/O. Every retry counts; unknown or interrupted usage retains its conservative reservation; fully reported input/output usage replaces the estimate after completion. Jev reserves request bytes plus its bounded response bytes because it exposes no server output-token ceiling. Tailoring reserves the actual serialized request plus configured output tokens. These are conservative work/cost admission controls, not dollar billing guarantees. Collection always ingests its full safe inventory even when zero model jobs/calls/tokens are permitted. Initial inventory enters automatic assessment reconciliation; its backlog label records discovery provenance and does not require approval. Cancellation blocks further provider admission and safely discards a collection response whose run was cancelled before ingestion; already admitted external requests can finish.

Settings remains separate from Jobs. Run progress shows source errors, assessment counts, configured limits, reserved and reported token usage, stage, last success and next run. Controlled source errors replace arbitrary provider text; incomplete inventories cannot close missing jobs. Downloads, review and model calls do not mark Applied.

## October 11 — automatic discovery and scoring

Onboarding generates full role names (including SWE, PM, ML/AI and DS aliases), separate Indeed/LinkedIn searches for supported countries, a 30-day initial window and daily schedules. Unrestricted and unsupported-country discovery uses LinkedIn without silently restricting the country. Generated sources admit up to 100 reviewed jobs and 200 calls per run; token ceilings remain enforced. Saving a scheduled source queues its first collection automatically.

The independent search-runs worker keeps four collection slots running. Request spacing and backoff are scoped to the selected site, so a blocked Indeed source cannot pause LinkedIn. A throttled run remains queued. Partial/capped search coverage does not falsely become a transport failure, and incomplete snapshots still cannot close unseen jobs.

The explicit backlog-review route and UI are removed. The matcher automatically reconciles first inventory, retains cancellation and atomic run budgets, charges reported model usage after completed requests, and retains reservations for unknown usage. Hourly/daily capacity waits defer durable tasks until their reset without consuming retries or requiring user action. Per-job attempt limits still stop repeated provider failures.

Jobs displays unique inventory across searches, aggregate collection/scoring progress, and the automatic model-capacity resume time. Optional refresh starts every enabled search. Sources fetch only their own run history. Pending job details explain automatic scoring; explicit retries remain available for evaluation errors.

## October 11 — internship discovery scope

Discovery and automatic scoring share a deterministic internship/co-op scope check before pagination or model admission. Provider employment-type labels and incidental references to previous internships do not establish that the opening is an internship. Explicit internship/co-op titles, explicit descriptions of the opening, and summer analyst/associate internship programs qualify; full-time internships remain supported. Staff roles managing internship programs and postings explicitly denying internship status are excluded. This controls discovery scope independently of candidate eligibility and does not automatically reject applications.

Raw source history and explicit Saved, Applied and Rejected records remain available. Aggregate progress excludes out-of-scope listings from scoring counts and reports their excluded count. Existing queued assessment work for those listings completes without model calls or budget reservations.

Verification: 1,026 Python tests pass, including 22 scope examples, API pagination and saved/application retention, and a regression proving excluded listings make no provider calls. Four Chromium search/workspace checks, Ruff, mypy, Svelte check and production build pass. The live preview excludes 75 of its 410 collected listings, leaving 335 in internship discovery; excluded examples include senior engineer, physician and permanent graduate roles. This is deterministic discovery evidence, not calibrated candidate-eligibility acceptance.
