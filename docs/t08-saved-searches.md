# T08 — Saved searches, schedules and persisted run admission

October 6, 2026. Implementation and synthetic integrated acceptance pass. The single Greenhouse setting is replaced by multiple independently versioned saved searches. Greenhouse, Lever and Ashby accept company names/board tokens; JobSpy exposes term, location, country, supported sites, window age and result count. No second queue or collector runtime is introduced.

Owners can run, pause/resume or remove a saved search, approve initial backlog evaluation, cancel remaining model admission, and inspect bounded run history. Immutable run snapshots survive edits to saved settings. Daily HH:MM schedules use validated IANA zones, skip nonexistent DST times, run repeated times once, persist next run and admit one collection at a time per search. Scheduler execution lives in the existing independent search-runs worker, so browser closure does not stop collection. Polling reloads persisted history on initial load, visibility and reconnect.

Run-level jobs/calls/token ceilings are configurable independently of T06 global retry caps. Atomic run_reservations record admission before assessment or tailored-generation HTTP I/O. Every retry counts; unknown or interrupted usage retains its conservative reservation, and known usage cannot lower a reservation. Jev reserves request bytes plus its bounded response bytes because it exposes no server output-token ceiling. Tailoring reserves the actual serialized request plus configured output tokens. These are conservative work/cost admission controls, not dollar billing guarantees. Collection always ingests its full safe inventory even when zero model jobs/calls/tokens are permitted. Initial backlog requires an explicit owner action. Cancellation blocks further provider admission and safely discards a collection response whose run was cancelled before ingestion; already admitted external requests can finish.

Settings remains separate from Jobs. Run progress shows source errors, assessment counts, backlog state, configured limits, reserved and reported token usage, stage, last success and next run. Controlled source errors replace arbitrary provider text; incomplete inventories cannot close missing jobs. Downloads, review and model calls do not mark Applied.
