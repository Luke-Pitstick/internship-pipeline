# T15 — Optional Google Sheets sync and CSV

Implemented October 6, 2026 after the T14 milestone. Settings → Notifications & Integrations now supports one service-account authorization flow, read-access testing, destination tab selection, explicit outward/inward columns, a dry-run preview, queued manual sync, optional scheduled sync, credential disconnect, status/conflict inspection and reviewed inward changes. CSV export is available without any Google credential.

## Self-hosted authorization flow

1. In a Google Cloud project, enable the Google Sheets API and create a dedicated service account. Create and privately download its JSON key. Do not grant domain-wide delegation; this application does not impersonate a personal Google user or list arbitrary Drive files.
2. Create or choose one spreadsheet and share it with the service account's `client_email` as Editor. Put column headers in row 1 and allocate sufficient grid rows. Copy the spreadsheet ID from its URL, not the entire URL.
3. Paste the downloaded key and spreadsheet ID into the authenticated settings panel and save. Saving validates the private key locally and contacts no Google endpoint. The saved key is encrypted and the field clears; it is never read back. Test access to retrieve the spreadsheet title and grid tab names, select the tab, then save/test that current revision.
4. Map `job_id` plus the selected job facts to distinct columns A–AZ; unset optional outward fields if desired. Keep manual notes and formulas in unowned columns. The read-access test does not mutate the sheet or claim edit permission; an explicitly queued sync verifies write access by write/readback. Preview the planned cells, resolve displayed conflicts or remap occupied columns, then queue the reviewed plan. Optional scheduled sync is off by default and runs only after explicit enable and a tested current revision.

The official `google-auth` library performs service-account signing and refresh using the `spreadsheets` scope. `GoogleSheets` calls only the official Google OAuth token endpoint and Sheets v4 API; redirects, environment proxies, external-account credentials, custom endpoints, universe-domain overrides and delegation are rejected. Only the required service-account fields are retained, encrypted through the existing Fernet cipher and exact `model-credentials.key`. T17 backs up this existing key and database. No OAuth redirect server or local Codex session is needed.

## Ownership and durable work

Application-owned outward fields are stable job ID, employer, title, location, current persisted fit score, source posting date, first observation, deadline, application link and source open/closed status. Source dates and first observation remain separate. Missing/stale assessments export an empty score; sync never reruns inference. `source_status` is distinct from application submission. Outward values are written with Google's `RAW` option, so source text beginning with `=` remains literal data. CSV additionally prefixes formula-like text with an apostrophe for spreadsheet import safety.

The destination identity includes spreadsheet, tab and explicit mappings. Upserts re-read the mapped stable ID, reject duplicate IDs, preserve row 1, write only individually mapped cells and leave every unrelated column untouched. Actual formulas are identified from `userEnteredValue.formulaValue` grid metadata, rather than guessing from text starting with `=`; formulas in owned cells/ID columns block the plan and require remapping. Existing nonblank owned cells that differ from both the desired value and the last verified application write require review rather than being overwritten. The preview contains the planned old/new cells and the first 30 job rows; it can cover up to 10,000 job records plus the header and columns A–AZ. Larger destinations fail visibly instead of pretending complete coverage.

`SheetsIntegration` uses the same jobs SQLite and existing `tasks` queue (`sheets_sync`), supervised independently through `sheets-sync`. A run stores its source/configuration/remote-cell snapshot. Changed job facts or moved/edited mapped cells invalidate the preview. Each row records a durable pre-I/O `sheets_journal` before HTTP, re-reads the destination, writes mapped cells, verifies readback and then stores a completed row checkpoint. Partial or uncertain HTTP writes retry through the shared bounded backoff (three attempts), allowing only the journal's recorded desired values during reconciliation. Verified completed rows survive restart and retries do not append a second stable ID. Revoked permissions/credentials, duplicate IDs, formulas and conflicts stop this integration and remain visible, while collection/matching/generation continue independently. Configuration changes/disconnect cancel queued plans, and pending inward acceptance requires its explicit current mapping.

Google Sheets does not provide conditional per-cell updates. The worker reads immediately before each row and verifies afterward, but cannot exclude a concurrent edit occurring inside the remote write interval. Application-owned mapped columns should not be manually edited while a sync is in flight. Formula/manual-note columns outside the mapping are never written. This is a documented provider concurrency limit, not an exactly-once or atomic cross-row guarantee.

Only explicitly selected inward application-status (`applied` / `not_applied`) and notes columns are read inward. They remain user-owned in Google and are never written outward. Changes create durable owner-review proposals; no sheet edit directly changes the local workspace. Accept/ignore checks that local data has not changed, rejects disconnected/remapped acceptance and records resolution/time in `sheets_inward`. Accepting Applied is an explicit recorded owner decision, never a claim that this pipeline submitted an application. Automatic scheduling may discover proposals but cannot accept them.

## Evidence and external blockers

Eleven focused Python tests pass: encrypted credentials and redaction, dry-run without writes, actual stable-ID upserts, unrelated formulas/manual notes, duplicate/owned-formula conflicts, partial-write/unknown-ack recovery after restart, changed-cell detection, revoked credentials, configuration cancellation, bounded retry/scheduled opt-in/disconnect, inward status/notes review with local conflicts and audit, formula-like RAW/CSV source text, malformed credential/endpoint rejection, and the mounted authenticated API/CSRF/logout/export path. The production `GoogleSheets` provider is exercised with the actual official `google-auth` signing path and `httpx.MockTransport`, including official URLs, OAuth assertions, RAW write bodies, FORMULA reads, grid formula metadata and sanitized 401/403/429/503/400 errors.

One dedicated Chromium test passes against the real temporary FastAPI owner API, actual Google authentication/HTTP adapter and independent queue worker, using synthetic HTTP responses only. It claims the owner, pastes a synthetic generated key, tests spreadsheet/tab discovery, selects inward columns, previews literal hostile source text, syncs the displayed plan, observes completion, reviews two inward proposals, exports safe CSV and checks a 390 px layout without horizontal overflow. Formula and manual-note preservation are enforced by the synthetic HTTP fixture and separately checked in backend tests. Svelte check reports no errors/warnings; static build, focused Ruff and mypy pass. Reproduce backend tests with `rtk proxy env PYTHONPATH=src .venv/bin/pytest tests/test_sheets_integration.py -q`; after a build, run `rtk proxy npx playwright test --config playwright.sheets.config.ts` from `web/`. The local test listener needs sandbox permission.

The obsolete SSH downloader `scripts/sync_render_outbox.py` and its isolated test are removed. Active README/deployment setup points to the self-hosted integration; historical acceptance/audit documents remain historical evidence.

Live Google acceptance remains explicitly blocked: no credential for a disposable shared spreadsheet or authorized remote write/readback was supplied. To retry, provide a dedicated service-account key and shared disposable sheet, authorize the bounded synthetic write/readback, and exercise access, preview, upsert, formula/manual preservation and credential revocation through this same path. Mocked Google HTTP responses and native queue tests are not live Google acceptance. No real Sheets mutation, external email, paid inference, private candidate file access, deployment, publication or commit occurred. Actual container acceptance remains blocked on the unavailable Docker engine. T16 owns the guided setup/skip journey; T17 owns backup/restore integration; T21 owns final release acceptance.
